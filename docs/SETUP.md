# Vallum — Deployment & Setup Guide

**Vallum** is an AI Safety & Scope Boundary Engine designed for penetration testing, red teaming, and security assessments. It operates on a **Strict Zero Host Execution** architecture, ensuring offensive commands generated by Large Language Models are verified, tokenized, and remediated without ever executing on the host machine.

---

## 1. System Requirements

* **Operating System**: macOS, Linux, or Windows (WSL2 recommended)
* **Python**: `3.11` or higher (`3.12` / `3.14` supported)
* **Node.js**: `v18.0.0` or higher (`npm v9+`)
* **Supabase**: Cloud project or local Supabase CLI instance

## 3. Backend Configuration

### 3.1 Virtual Environment & Dependencies

From the repository root:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3.2 Environment Variables (`backend/.env`)

Create or update `backend/.env` with the following configuration:

```ini
# FastAPI Configuration
HOST=127.0.0.1
PORT=8000
ENVIRONMENT=production

# Inference Providers
# Built-in Groq key for default Llama 3.3 70B evaluation
GROQ_API_KEY=gsk_your_groq_api_key_here

# OpenRouter (Optional system key, users can BYOK in client vault)
OPENROUTER_API_KEY=sk-or-v1-optional_system_key

# Supabase PostgreSQL Database & Auth
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

# Cryptographic Vault Master Key (32-byte / 64 hex characters)
# Used for AES-256-GCM zero-knowledge encryption of client API keys
VAULT_MASTER_KEY=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```

To generate a secure 64-character hex master key:
```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

### 3.3 Running the Backend Server

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```
Interactive OpenAPI documentation will be accessible at: `http://127.0.0.1:8000/docs`

## 4. Database Setup & Migrations (Supabase)

Execute the following migrations in order via the Supabase Dashboard SQL Editor or Supabase CLI:

1. `supabase/migrations/001_initial_schema.sql`: Core tables (`profiles`, `roe_presets`, `custom_roes`, `audit_logs`) and Row Level Security (RLS) policies.
2. `supabase/migrations/002_user_api_vault.sql`: Zero-knowledge encrypted user API key vault (`user_api_vault`) with AES-256-GCM ciphertext storage.
3. `supabase/migrations/003_benchmark_runs.sql`: Benchmark telemetry store (`benchmark_runs`) with compliance rate indices.
4. `supabase/migrations/004_auth_rbac_hardening.sql`: Purges mock/testing accounts, configures verified signup requirements, and establishes the immutable Super Admin rule.

## 5. Authentication & Access Governance (RBAC)

### 5.1 Permitted Authentication Providers
Vallum enforces strict identity verification. Anonymous account creation and mock accounts are completely disabled:
1. **Google OAuth**: One-click authentication for enterprise and university Google workspaces.
2. **GitHub OAuth**: One-click authentication for security researchers and developers.
3. **Email + Password**: Requires **verified email delivery** (`email_confirmed_at`). Unverified accounts cannot authenticate.

### 5.2 Role-Based Access Control (RBAC) Policy
* **Super Admin**: **Khushal Arora** (`arorakhusuhal1108@gmail.com`) is designated as the sole, immutable Super Admin.
* **Penetration Tester**: All other registered users are automatically assigned the role **Penetration Tester**.
* **Immutable Admin Invariant**: Database trigger `trg_enforce_sole_admin_policy` automatically rejects any role modification or elevation to `admin` for any other email address.
